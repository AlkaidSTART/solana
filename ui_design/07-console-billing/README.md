# 页面设计规范：SaaS 商家工作台 — 财务充值中心 (Billing & Solana Pay)

- **页面路径**：`/console/billing`
- **页面定位**：商户订阅周期管理、Credits 分类资产账本、逐笔透明扣费与补偿流水审计、以及 Solana Pay 原生 USDC 毫秒充值与电子票据模态框
- **设计基调**：Modern Enterprise B2B SaaS（现代企业级商业规范、清晰稳健、高数据密度与专业工作台交互）
- **结算币种**：原生 USDC（Solana L1 结算，1 USD 标价单位对应 1 USDC）

## 3. 核心业务规则与防作弊机制 (PRD 6.1 ~ 6.4 严格对齐)

1. **统一计费单位（1 Credit 规则）**：
   - 1 Credit = 同一租户、同一店铺、同一买家，在一个固定 24 小时计费窗口内的自动化服务额度。
   - 窗口内的多条订单提醒、COD 确认和 AI 回复共享该 1 Credit，最多 20 条消息。
   - **只有当首条自动消息确认已送达（DELIVERED）时，才将预留转为扣除**。发送失败或取消必须释放预留，绝不乱扣点数。
2. **纯原生 Web Audio 触感反馈**：
   - 用户点击支付与签名时，页面触发 30ms 极微弱正弦衰减音（`800Hz -> 200Hz`）。
   - 链上入账确认（Finalized）瞬间，触发清透的双音符共鸣完成音（`523.25Hz -> 1046.5Hz`）。

## 4. 状态覆盖与交互行为

| 状态 | 表现规范 |
| :--- | :--- |
| **Loading** | 流水表格呈现淡灰发丝骨架条，模态框内部二维码区域显示灰色方块占位。 |
| **Empty** | 若无充值流水，表格显示“当前暂无充值记录，所有消费均从系统初始试用额度扣除”。 |
| **Error** | 若 Solana RPC 发生网络抖动或用户拒签，模态框底部显示发丝红字：“交易已取消或签名超时”，允许用户一键重试。 |
| **Success** | 交易达成并在链上 Finalized 后，模态框平滑转为电子收据完成页，绿色徽章闪现，总余额即刻实时递增。 |
