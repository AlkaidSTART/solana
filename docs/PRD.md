# 产品需求文档 (PRD)：东南亚跨境电商 WhatsApp/小语种防漏单与催付 AI Agent

## 1. 文档概述与产品定位

- **产品名称**：SolaFlow AI (暂定)
- **产品形态**：Web 端 SaaS 工作台 + 自动化通知与对话引擎 + Solana Pay 充值结算中心
- **目标客群**：
  - 中国出海东南亚（印尼、泰国、越南、马来西亚、菲律宾）的跨境电商卖家及品牌团队；
  - 新加坡、马来西亚本地经营 Shopee、Lazada、TikTok Shop、WooCommerce/Shopify 的中小商户。
- **核心价值主张**：
  - **挽回流失订单**：未支付订单在 15 分钟内通过 WhatsApp 自动发起多语言本地化挽留与催付；
  - **降低 COD 弃签率**：发货前自动校验买家收货意愿与地址真实性，拦截高风险空号与恶意弃单，挽回单票往返运费损耗；
  - **零摩擦低费率充值**：基于 Solana Pay（USDC）提供秒级到账的点数与订阅结算，规避跨境信用卡拒付与高昂换汇损耗。

---

## 2. 用户痛点与业务指标 (KPI)

### 2.1 核心痛点

- **时差与夜间漏单**：东南亚买家夜间 20:00–01:00 咨询与加购活跃，人工客服断档导致丢单。
- **小语种与本土俚语障碍**：普通翻译软件无法准确识别印尼爪哇语缩写（如 `brp`、`ongkir`）、泰语网购缩略语，导致沟通僵硬甚至误解。
- **COD 签收率低（15%~25% 拒签）**：冲动下单后无人确认，货到门口联系不上买家，卖家承担单程与退回运费。
- **跨境支付充值痛点**：中小团队没有海外外币企业卡，传统法币网关频繁拒刷、收取 3%~5% 手续费。

### 2.2 关键指标 (KPI)

- **未支付订单挽回率**：目标 $\ge 15\%$
- **COD 签收率提升**：平均拒签率下降 $5\% \sim 8\%$
- **免费试用到付费转化率**：目标 $\ge 25\%$（首发免费 100 条）
- **次月续费留存率 (Retention Rate)**：目标 $\ge 80\%$

## 4. 功能详细规格

### 4.1 电商与通讯平台集成模块 (Integration)

- **电商平台授权**：支持绑定主流平台（TikTok Shop、Shopee、WooCommerce/Shopify）。
- **Webhook 实时接收事件**：
  - `order.created`（下单）
  - `payment.failed`/`pending`（待付款）
  - `order.fulfilled`（已发货）
  - `order.delivered`（已妥投）
- **WhatsApp 接入**：
  - 支持对接 Meta WhatsApp Cloud API（官方号认证）；
  - 提供 QR Code 扫码直连模式（基于 Baileys/WPPConnect 协议，适配个人小卖家免官方企业验证）。

### 4.2 场景化自动化工作流引擎 (Automated Workflows)

#### 场景 A：未支付订单“黄金 15 分钟”催付 (Abandoned Checkout Recovery)
- **触发条件**：产生待支付订单且在 15 分钟内未完成付款。
- **业务逻辑**：
  1. 系统提取买家姓名、加购商品、订单金额与电话号码。
  2. 匹配买家所在国家，自动调取本土化语言模板（例如：印尼买家采用 Bahasa Indonesia，掺入本土常用语气词）。
  3. 通过 WhatsApp 发送提醒，附带专属短链（含限时 5% 折扣或免运费券）。
  4. 买家若回复咨询（如“是否有现货/何时发货”），AI 自动回答并再次引导付款。

#### 场景 B：COD 订单发货前意愿核验与地址校验 (COD Anti-Cancellation)
- **触发条件**：产生新的 COD 支付方式订单。
- **业务逻辑**：
  - 订单生成 5 分钟内，向买家发送确认消息：
    > “您好 [姓名]，您在 [店铺名] 订购了 [商品]，总金额 [金额]，将于明天发出。请回复 1 确认发货，回复 2 更改地址，回复 3 取消。”
- **智能风控判定**：
  - **低风险**：买家明确回复确认，订单状态变更为“待发货 - 已验单”；
  - **中风险**：买家 12 小时未回复，触发二次提醒；
  - **高风险**：电话号格式错误/未注册 WhatsApp，或明确拒绝，系统打标“建议拦截”，避免卖家盲发亏损运费。

### 4.3 智能会话与本地化 Agent 引擎 (Conversational Core)

- **知识库与商品同步**：自动抓取店铺商品信息（规格、库存、基础常见问题 FAQ）。
- **小语种俚语库优化**：
  - **印尼语**：精准解析 `bisa COD?`（能货到付款吗？）、`ongkir brp?`（运费多少？）；
  - **泰语**：自动匹配尊称词 `ครับ (khrap)` / `ค่ะ (kha)`，符合当地网购礼貌规范。
- **人工接管机制**：当买家情绪识别为“愤怒”、要求退款投诉，或意图跳出预设边界时，自动切换为“待人工处理”，并在 Web 控制台发出声光告警。

### 4.4 计费系统与 Solana Pay 结算模块 (Billing & Settlement)

- **计费逻辑**：
  - **双轨计费制**：
    - **基础订阅费（月/年付）**：解锁多店铺接入、进阶风控与数据报表；
    - **对话点数包（Credits）**：按成功触达与多轮互动扣费（1 Credit = 1 条完整有效对话链）。
  - **新用户冷启动策略**：注册即送 100 Credits，支持全流程跑通，无需预先绑定任何支付方式。
- **Solana Pay 结算闭环**：
  - **支持代币**：USDC、EURC（基于 Solana SPL 标准）。
  - **充值流程**：
    1. 用户在“财务中心”选择套餐或输入点数充值金额（例如：$50 USDC 购买 2,500 Credits）。
    2. 后端基于 `@solana/pay` 动态生成附带唯一 `reference` 公钥的支付 URL，渲染为二维码与“Connect Wallet”按钮。
    3. 用户使用 Phantom、Backpack 或手机扫码完成签名确认。
    4. 后端通过 RPC 节点监听该 `reference` 交易。
    5. 交易达到 `confirmed`/`finalized` 后，系统在 1 秒内为商户自动增加 Credits 并记录财务流水。

## 7. 风险评估与应对策略

- **WhatsApp 封号风险**：
  - **应对**：严格限制主动发送频次（单用户 24 小时内催付不超过 2 次）；优先使用 Meta 官方认证的 WhatsApp Business API 模板消息。
- **LLM 幻觉误承诺折扣或库存**：
  - **应对**：采用 Strict JSON Schema 输出；将价格与发货时间硬编码为系统变量，禁止模型自由发挥承诺未授权的优惠。
- **链上交易拥堵与掉单**：
  - **应对**：采用多 RPC 节点主备切换（Helius + QuickNode）；前端设置轮询机制，后端建立补偿 Job，交易未即时到账时支持通过交易哈希（Signature）手动核验补单。
