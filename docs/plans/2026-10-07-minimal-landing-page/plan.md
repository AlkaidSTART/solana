# 需求计划：出海官网极简与呼吸感重构 (Minimalist Landing Page Redesign)

- **日期**：2026-10-07
- **Slug**：`minimal-landing-page`
- **需求来源**：用户反馈“出海官网可以设计的简约点，现在有点紧凑”
- **核心目标**：将当前信息密集、边框过重、元素局促的官网首页全面重构为符合现代国际化顶级 B2B SaaS（对标 Linear / Stripe / Raycast）的极简、轻盈、富有呼吸感（spacious & minimal）的出海品牌官网，在完全保留所有业务能力、交互沙盒、ROI 计算器与多语言切换的前提下，大幅改善视觉压迫感。

## 1. 背景与问题诊断

当前首页（`/`）存在以下视觉与排版问题：
1. **空间局促与呼吸感不足 (Tight Spacing)**：
   - 栅格与间距紧绷，各 Section 垂直留白不足（`py-12~20`），多处使用硬边框（`border-[#E4E4E7]`）割裂页面，缺乏自然平滑的留白过渡；
   - 容器内嵌过多嵌套边框与卡片，造成“框中框中框”的视觉疲劳感。
2. **Hero 首屏严重拥挤 (Cramped Hero)**：
   - Hero 区域采用左右 6:6 强制对分，右侧的 `HeroProductDashboard` 在仅 ~580px 的窄宽下强行容纳“5 栏订单列表 + 7 栏 WhatsApp 完整对话 + 状态同步卡 + 模拟点击”，导致内部字号缩至 10-11px、按钮与文案严重拥挤，用户第一眼无法聚焦；
   - 左侧行动按钮堆积了 3 个长按钮，顶栏右侧也塞了 3 个按钮，行动引导分散。
3. **字体与排印失衡 (Typography & Mono Overuse)**：
   - 标题与中文大文本滥用 `font-mono`，导致中文字符字距僵硬、阅读体验生硬；
   - 缺少由大及小、层次分明的视觉韵律（Visual Hierarchy）。
4. **视觉噪点过多 (Visual Clutter)**：
   - 大量彩色小标签、版本号胶囊、密集状态灯交织，分散了对核心业务价值（“15 分钟挽回”、“COD 发货前核验”、“Solana 即时结算”）的关注。

## 2. MVP 重构范围与设计策略

1. **结构与布局优化（通透与呼吸感）**：
   - **Hero 首屏重构**：采用国际化现代 SaaS 旗舰版型（更通透的层次结构）。顶部为清晰优雅的标题组（超大标题、精炼价值主张副标、主次分明的 CTA 按钮组）；紧随其后呈现宽体全景、悬浮质感、轻边框微阴影的**实时出海控制台预览视窗**，给予订单流与 WhatsApp 会话充足横向空间，告别窄屏挤压。
   - **数据指标带极简化**：将原本沉重的 Excel 式硬边框网格，改为清爽、大字号等宽数字、轻盈分割的指标流，提升商户信任感与专业度。
2. **交互演练台（Telemetry Sandbox）去繁求简**：
   - 增加卡片内部内边距与留白（`p-8` ~ `p-10`），优化场景切换胶囊（Segmented Pill Tabs）触感；
   - 手机端模拟视窗与遥测视窗解耦间距，减少冗余边框与高对比色块，用柔和底色与细腻发丝线替代粗边框。
3. **5 大企业级核心能力矩阵（Capabilities Bento）简约升级**：
   - 告别花哨杂乱的多种高饱和强调色，采用统一的现代极简单色+语义点缀规范；
   - 卡片留白扩充，采用更有节奏感的网格排布（3 列或 2+3 精致流线），突出核心价值与业务数据。
4. **ROI 计算器与转化 CTA 精炼**：
   - 滑块控件精简化、去除多余视觉装饰，凸显动态计算结果的大字号视觉冲击；
   - 底部转化区扩充垂直空间（`py-28~32`），聚焦单个最强行动点（立即免费接入 / Solana Pay 体验）。
5. **排印与色彩令牌优化**：
   - 中文及西文大标题回归精炼高质感的无衬线字体（`font-sans font-bold tracking-tight`）；
   - `font-mono` 严格收敛于数字指标、哈希、时间戳、状态胶囊与代码/报文；
   - 整体主色保持黑白灰高级质感，辅以极克制的翡翠绿（WhatsApp 在线）、科技蓝（链上结算）微点缀。

## 3. 非目标 (Non-Goals)
- 不减少任何业务功能或移除交互能力（多语言切换、实时演练台 4 场景交互、ROI 计算器滑动测算、Solana Pay 充值模态框等全部保留）；
- 不改动后端 API 路由或破坏商户控制台现有功能；
- 不引入重型未授权的外部 CSS 库或侵入性框架。

## 4. 风险与依赖
- **依赖**：Next.js 16.3.8、React 19.2.8、Tailwind CSS 4、Lucide React、GSAP。
- **风险**：调整布局后在移动端（375px）与平板（768px）视口下的适配。
  - **应对**：使用严格响应式类名（如 `sm:`, `md:`, `lg:`），确保在 375px 无横向滚动，在 1440px 桌面端留白得体。
- **风险**：类型检查与 ESLint 回归。
  - **应对**：各阶段持续运行 `pnpm exec tsc --noEmit` 与 `pnpm lint`。

## 5. 阶段拆分与推进计划

- **阶段 1：设计与骨架梳理**
  - 创建计划文档与执行记录；
  - 提炼重构所需的设计令牌与布局间距规范。
- **阶段 2：Hero 首屏与导航栏极简改造**
  - 改造顶栏：精简按钮堆叠，保留核心行动点与三语胶囊；
  - 改造 Hero 区域：极简大气居中/流线排版，放大标题呼吸感，精简 CTA；
  - 改造 `HeroProductDashboard`：给予宽阔空间，优化左右视窗间距与内部排版，消除挤压感；
  - 改造 4 维核心数据行：通透大字号极简设计。
- **阶段 3：业务演练台与 5 大核心能力简约重构**
  - 优化 `TelemetrySandbox`：增大内部留白、柔化边框、提升手机端与控制台视窗的高级质感；
  - 重构 5 大能力 Bento 区域：纯粹黑白灰+极简卡片阴影，扩大 padding，排版更疏朗。
- **阶段 4：ROI 计算器、底部 CTA 与页脚精致化**
  - 优化 `RoiCalculator` 视觉层次，去除局促感；
  - 优化底部 CTA 区域留白与文案排版；
  - 优化 Footer 极简布局。
- **阶段 5：响应式多视口自检与全体验收**
  - 执行 `pnpm exec tsc --noEmit`、`pnpm lint`、`pnpm test` 和 `pnpm build`；
  - 验证三语切换（EN / ID / ZH）及 Solana Pay 模态框调起正常；
  - 完成验收并更新 `result.md`。

## 6. 验收标准
1. 视觉观感明显通透、留白充裕、告别紧凑感；
2. 375px、768px、1440px 视口下均无横向溢出，排版优美；
3. 保留并正常运行：三语即时切换、Hero 控制台交互、业务演练台 4 场景切换及按钮交互、ROI 计算器动态联动、Solana Pay 充值模态框；
4. `tsc --noEmit`、`pnpm lint`、`pnpm test`、`pnpm build` 全部通过。
