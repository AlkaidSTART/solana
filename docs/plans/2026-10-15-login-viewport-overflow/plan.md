# 需求计划：登录页多屏自适应防溢出滚动优化 (Login Viewport Overflow Fix)

## 1. 背景与目标
- **背景**：当前 SolaFlow AI 登录页 (`app/login/page.tsx`) 在各尺寸屏幕（如 1366x768 笔记本、1440x900 常见屏幕、1024x768 平板横屏以及 375px/390px 移动端设备）下，由于固定内边距过大、元素间距松散、`min-h-[640px]` 等硬性高度约束以及移动端大块业务 HUD 占用过多垂直空间，导致页面在各个断点下均会产生垂直溢出和不必要的页面级滚动条。
- **目标**：优化登录页 (`app/login/page.tsx`)、鉴权卡片 (`components/auth/auth-card.tsx`) 与商业展厅 (`components/auth/auth-showcase.tsx`) 的响应式与弹性视口布局，使页面在移动端 (375px~430px)、平板端 (768px~1024px)、常见笔记本/桌面端 (1280px~1920px) 的常见视口高度下均能自然完整呈现，实现 **0 溢出、无滚动条** 的极简自适应体验，同时在极端矮屏下保留优雅降级安全滚动。

## 2. MVP 范围与非目标
- **MVP 范围**：
  1. `app/login/page.tsx`：采用 `h-dvh max-h-dvh overflow-hidden` 视口契约，精简顶部 Header 高度 (`h-12 sm:h-14`) 与底部 Footer 高度 (`h-9 sm:h-10`)，优化主网格栅格高度分配 (`min-h-0`)，将移动端 HUD 重塑为轻量微徽标/微状态条。
  2. `components/auth/auth-card.tsx`：优化内外边距与垂直层级（`p-4 sm:p-6`，间距由 `space-y-6` 精细化至响应式 `space-y-3 sm:space-y-4`），合并同类单选与辅助操作行（如记住邮箱与忘记密码同排展示），优化注册表单网格排布（店铺与市场、密码与确认密码在支持时双列栅格化），减小卡片整体垂直占用。
  3. `components/auth/auth-showcase.tsx`：去除硬编码 `min-h-[640px]`，引入 `min-h-0 h-full` 弹性伸缩与响应式间距，收紧会话气泡与遥测雷达的内边距，确保 600px~800px 矮视口桌面端能完整容纳。
  4. 多语言兼容性：核验 `zh_CN`、`en_US`、`id_ID` 三种语言在各分辨率下无水平文字溢出或换行破坏。
  5. 自动化测试与质量闸门：编写针对视口适配与紧凑排版约定的单元/属性测试，通过 `pnpm lint`、`tsc --noEmit`、`pnpm test` 与 `pnpm build`。
- **非目标**：
  1. 不修改 Neon Auth 认证逻辑、后端 API 协议或数据持久化流程。
  2. 不更改控制台、官网或入驻向导等其他页面的既有业务逻辑。
  3. 不引入第三方布局库或外部重型依赖。

## 3. 风险与依赖
- **风险 1：移动端矮屏输入法弹起或极矮视口内容被裁切**
  - *应对方案*：外层容器锁定 `h-dvh overflow-hidden` 防止整页晃动，卡片内容承载区设置 `min-h-0 overflow-y-auto` 并隐藏默认粗糙滚动条，常规屏幕完全不触发滚动，矮屏时内容安全可达。
- **风险 2：注册表单字段较多导致移动端纵向堆叠过长**
  - *应对方案*：采用精细化表单间距与双列弹性栅格（如店铺名+目标市场同行、密码+确认密码同行），单字段高度与标签间隙微调，降低卡片高度 120px+。
- **风险 3：国际化长文案（如印尼语、英语）换行撑高**
  - *应对方案*：优化排版字号 `text-[10px]/text-xs`，保证在 375px 视口下中英印尼文均不出现横向滚动条或布局错乱。

## 4. 阶段拆分
- **阶段 1：页面主骨架与视口约束重构**
  - 交付文件：`app/login/page.tsx`
  - 目标：将外层容器定格为 `h-dvh max-h-dvh overflow-hidden`，收紧 header 与 footer，重构移动端轻量业务标头，确保主体区域拥有明确的 `flex-1 min-h-0` 弹性空间。
- **阶段 2：鉴权卡片 AuthCard 紧凑自适应与空间优化**
  - 交付文件：`components/auth/auth-card.tsx`、`components/auth/oauth-buttons.tsx`
  - 目标：紧缩卡片内外边距、按钮尺寸、OTP 输入框尺寸，合并记住邮箱与找回密码，优化注册表单双列响应式布局，显著降低登录与注册两种形态的高度。
- **阶段 3：桌面展厅 AuthShowcase 弹性伸缩改造**
  - 交付文件：`components/auth/auth-showcase.tsx`
  - 目标：解除 `min-h-[640px]` 限制，优化展厅内部各区块（标头、会话视窗、指标卡片、引用脚注）的垂直 margin 与 padding，支持 650px+ 常见桌面高度完整呈现无滚动。
- **阶段 4：视口适配测试用例、多端验收与质量闸门**
  - 交付文件：`components/auth/auth-viewport.test.tsx`、`docs/plans/2026-10-15-login-viewport-overflow/result.md`
  - 目标：运行 Vitest 测试、TypeScript 类型检查、ESLint 代码规范与 Next.js 构建，验证 375px/768px/1024px/1440px 视口下无溢出。

## 5. 各阶段测试步骤与预期
- **阶段 1 测试**：
  - 输入：检查 `app/login/page.tsx` 的容器 class 与 DOM 结构。
  - 预期：具备 `h-dvh` 与 `min-h-0`，Header 为 `h-12 sm:h-14`，Footer 为 `h-9 sm:h-10`，移动端 HUD 占位精简。
- **阶段 2 测试**：
  - 输入：切换登录与注册模式，检查输入框布局与卡片高度。
  - 预期：登录模式高度 ≤ 430px，注册模式高度 ≤ 530px；375px 宽度无水平溢出。
- **阶段 3 测试**：
  - 输入：检查 `AuthShowcase` 在 `lg` 断点下的内容尺寸与高度表现。
  - 预期：在 768px 高度视口下，桌面端双栏不溢出，无垂直滚动条。
- **阶段 4 测试**：
  - 输入：运行 `pnpm test`、`pnpm lint`、`pnpm exec tsc --noEmit`、`pnpm build`。
  - 预期：全部命令 0 错误退出，测试通过率 100%。

## 6. 最终验收标准
1. [ ] 375px × 667px (移动端常见最小视口)：登录与注册卡片在视口内完整展现，无横向与垂直滚动条。
2. [ ] 768px × 1024px (平板竖屏)：登录页居中整洁，无溢出滚动。
3. [ ] 1024px × 768px / 1366px × 768px (主流笔记本视口)：左侧展厅与右侧卡片双栏完整展开，视口无滚动条。
4. [ ] 1440px × 900px / 1920px × 1080px (桌面显示器)：精致优雅，上下居中，无多余空白拉伸与变形。
5. [ ] 多语言 (`zh_CN`, `en_US`, `id_ID`) 切换正常，无文字折行溢出。
6. [ ] 核心登录（OTP/密码/OAuth）与注册功能交互完整，原有测试全部绿灯通过。
