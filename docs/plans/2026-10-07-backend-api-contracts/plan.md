# 后端接口与 Zod 契约文档计划

## 背景与目标
依据 PRD v1.1、现有工作台页面及 WhatsApp 接入指南，整理可分阶段实施的后端接口和复杂类型强校验约定，交付 docs/backend-api-spec.md。

## MVP 范围
- 明确租户认证、接口通用规范、RBAC、幂等、并发与错误协议。
- 覆盖入驻、店铺/通道、同意、订单、工作流、会话、知识、财务/支付、报表、成员、隐私及外部事件。
- 提供 Zod 4 Schema 示例及字段约束，区分结构校验、服务层事实校验与数据库事务约束。
- 给出正常/边界/异常测试样例与小 MVP 交付顺序，标注与现有 Demo 的差异及待确认项。

## 非目标
不实现 HTTP 服务、不修改页面/依赖/锁文件、不修改 PRD、不接入真实商户或支付，不将建议契约冒充已上线接口。

## 风险与依赖
- package.json 和 pnpm-lock.yaml 已有其他任务修改，必须保留。
- Zod 未列为直接依赖；核对官方 Zod 4 API，若本地已有兼容副本，仅用于隔离校验文档示例，不修改依赖。
- UI/Demo 与 PRD 存在范围冲突，以 PRD 为准；认证方式和接口路径等新增技术选择明确标为建议。
- Schema 不等于权限、签名、链上真伪或事实验证，不给前端开放直接入账、改原平台订单或自动退款能力。

## 阶段与测试
1. T1 现状与规划：读取 AGENTS、PRD、页面和 Demo 状态类型；检查 git status。预期明确首版边界、权限矩阵及已有改动。
2. T2 契约编写：核验官方 Zod 文档并编写接口表、Schema、状态/安全约束。预期复杂数据禁止 any/类型断言代替运行时校验，关键业务均有入口或内部职责。
3. T3 文档验收：校验本地链接、接口重复、关键模块和测试矩阵；抽取完整 TS 示例做语法/类型和运行时测试（可用环境下）。执行 git diff --check、AGENTS 行数和改动范围检查。不能运行的验证如实记录。

## 验收标准
文档覆盖 PRD 首版业务与角色；请求/响应/权限/错误有明确约定；可执行 Zod 示例含跨字段规则和负例；每阶段 result.md 完整，真实 HTTP/第三方/链上联调明确未执行。

其他任务已将 Zod 4.6.5、测试工具等加入直接依赖；当前以 manifest/锁文件及本地解析结果为准，不重复安装。仍只修改本需求三个文档；其他任务的新支付代码、页面和依赖不属于本需求验收范围。
