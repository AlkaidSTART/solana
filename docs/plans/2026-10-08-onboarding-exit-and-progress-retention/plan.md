# 需求计划：免费接入向导支持任意阶段退出与进度保留

## 1. 背景与目标
- **业务背景**：SolaFlow AI 面向东南亚出海商户提供 6 步“免费接入 / 商户初始化激活向导” (`/onboarding`)，并赠送 100 免费 Credits。
- **用户痛点**：商户在落地页等入口点击“免费接入”后，可能因误触或临时有事需要中途退出。当前向导表单所有状态仅存在单个组件的 React 本地 `useState` 中，且退出路径单一（仅写死跳转 `/console`）。一旦退出、刷新或返回首页，已填写的店铺信息、WhatsApp 凭证与步骤全部丢失，必须从头填写。
- **需求目标**：
  1. **支持任意阶段退出**：商户在 1~6 步的任意阶段均可安心退出，提供直观的退出入口（顶部“退出向导”与卡片底部“暂存退出”），并支持选择“返回落地页”或“前往控制台”。
  2. **全程自动保留进度**：遵循 Zustand 客户端共享状态分层规范，创建持久化独立领域 Store（`useOnboardingStore`），无论中途退出、误触刷新还是页面跳转，均完整保留当前所处步骤和所有表单输入。
  3. **无缝恢复与重置**：再次进入 `/onboarding` 时自动恢复上次进度与所填字段，并展示恢复提示 Banner；同时支持“重新开始”以满足重新录入需求。
  4. **完成状态闭环**：最终激活并领取 Credits 后标记为完成，避免重复陷入未完成草稿状态。

## 2. MVP 范围
- 独立的 Onboarding 领域 Store (`stores/use-onboarding-store.ts`)，基于 Zustand + `persist` 中间件保存草稿至 `localStorage`。
- 退出向导模态框与路由分流组件（支持安全退出回首页或控制台，展示当前步骤自动保存反馈）。
- 改造 `/onboarding` 页面：
  - 接入 `useOnboardingStore`，实现步骤与所有表单数据的双向同步与持久化；
  - 顶部导航栏增加“退出向导”按钮；
  - 卡片底部增加“暂存并退出”辅助入口；
  - 增加“恢复上次进度”横幅提示及“从头重新开始”重置动作；
  - 激活完成后调用 `markCompleted` 正确完成流程。
- 自动化单元测试：编写 `stores/use-onboarding-store.test.ts`。

## 3. 非目标 (Out of Scope)
- 不改造服务端数据库的商户全量草稿暂存接口（本需求聚焦前端商户本地草稿与会话级体验，避免未登录未认证用户产生无主脏数据）。
- 不更改 Meta 官方 WABA 直连与店铺 Webhook 协议的真实逻辑。

## 4. 风险与依赖
- **SSR Hydration 风险**：使用 `localStorage` 持久化可能导致 Next.js 服务端渲染与客户端初始渲染不一致。
  - *规避措施*：在 Store 中提供 `hasHydrated` 标记或通过 hydration 守卫加载，确保初次渲染安全。
- **状态污染风险**：激活完成后如果残留草稿可能影响下次体验。
  - *规避措施*：在激活完成动作触发时清理草稿或设置 `isCompleted: true`。

## 5. 阶段拆分
- **阶段 1：创建 Onboarding 领域 Store 与单元测试**
  - 新建 `stores/use-onboarding-store.ts`；
  - 编写 `stores/use-onboarding-store.test.ts`，验证数据持久化、步骤推进、重置与标记完成逻辑；
  - 运行单元测试并确保全部通过。
- **阶段 2：实现退出向导交互弹窗与进度恢复 Banner**
  - 在 `app/onboarding/page.tsx` 中增加优雅的退出确认对话框与恢复状态横幅；
  - 顶部导航与底部操作区接入退出交互，支持任意阶段退出至首页或控制台。
- **阶段 3：改造 Onboarding 页面与落地页联动**
  - 全面使用 Store 替代页面本地易失的 `useState`；
  - 支持表单字段即时持久化；
  - 完成向导时正向闭环。
- **阶段 4：质量闸门核验与全量回归**
  - 执行 `pnpm test`、`pnpm lint`、`pnpm exec next typegen && pnpm exec tsc --noEmit`、`pnpm build`。

## 6. 各阶段测试步骤及预期
- **阶段 1 测试**：
  - 执行 `pnpm vitest run stores/use-onboarding-store.test.ts`。
  - 预期：全部用例绿灯，包含步骤设置、草稿更新、重置、完成标记等。
- **阶段 2/3 测试**：
  - 手动/逻辑测试：进入 `/onboarding`，修改店铺与 WABA 数据，进入步骤 3 或 4；点击退出向导返回首页；重新点击进入 `/onboarding`；
  - 预期：步骤仍为步骤 3 或 4，之前输入的值完整保留，提示“已恢复上次保存的接入进度”。
- **阶段 4 测试**：
  - 执行完整构建与全套测试。
  - 预期：构建与类型检查通过，0 lint 错误。

## 7. 最终验收标准
1. 在第 1~6 步的任意阶段均有清晰可见的退出方式。
2. 退出时明确反馈已自动安全保存当前进度。
3. 离开后再次通过任意入口进入“免费接入”，页面准确还原上次填写的字段和步骤。
4. 提供“重新开始”入口，可安全清除已存草稿。
5. 最终第 6 步激活完成并派发 Credits 后正常完成向导。
6. 全量自动化测试通过，构建与类型检查无任何报错。
